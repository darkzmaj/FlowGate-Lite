# Maintenance audit — 2026-10-16

Reviewed all 20 Java files, config/messages/MOTD/plugin metadata, build settings/wrapper, README, default branch, tags and open PRs. Existing routing, health probes/quarantine, balancing weights, reserved slots, sticky sessions, fallback retries, waiting titles, hub/direct commands and backend Connect messages are preserved.

Confirmed fixes: restricted-server access missing from custom routes; stale backend messages controlling current players; non-atomic message rate windows; ServerConnectedEvent observed before the active backend switch; initial joins skipped fallback when healthy hubs were full; repeated backend rejections caused a fallback loop; intermediate failed reload candidates were visible; locale-dependent policy names; title counter overflow; waiting-title/singleton cleanup. Backend messages retain the Connect format and now honor source/destination policies, active connection identity, size/framing checks and destination access. Already-cancelled events are respected. Only connection requests are forwarded; there is no arbitrary console execution.

Validation: 8 JUnit regression tests, clean build and compiler deprecation/unchecked lint; BungeeCord 2104 (Java 21) startup, protocol 777 MOTD/hover ping, status/reload/shutdown; live protocol-777 client through Paper 26.3 + FlowGate-Bridge to a second backend, including rejection of forged client messages. The integration harness also tests termination of repeated backend rejection chains. High-load operation, online authentication, Waterfall, FlameCord, older clients and sticky-session/animated-title behavior with real players remain unverified.

The API remains stable BungeeCord 1.21-R0.4 because the used API is binary-compatible with the tested current proxy. Runtime protocol support belongs to the proxy: current BungeeCord source and runtime report protocol 777 (MC 26.3). Bungee publishes successful CI builds carrying a SNAPSHOT version label; build 2104 is the tested upstream artifact, not a newly invented stable release. Waterfall is discontinued; Velocity cannot load Bungee plugins and requires an equivalent router. No protocol metadata version bump alone establishes compatibility.

Generated build output, caches and IDE files were removed from version control; wrapper distributions have an official SHA-256 pin and JAR ordering/timestamps are reproducible. No runtime dependencies are shaded and no telemetry or external service was added. Health metrics are local counters. Configuration keys and defaults remain compatible. Restrict backend access and source allowlists because the backend is trusted infrastructure.
